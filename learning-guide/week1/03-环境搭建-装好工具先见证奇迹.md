## 3.1 确认 Python 版本

打开终端，跑：

```bash

```

看到 `Python 3.10.x` 或更高就行（3.9 大概率也能跑，但建议 3.10+）。本课只依赖三个纯 Python 包，不绑定任何 IDE 和系统。

## 3.2 装依赖（venv 可选，但推荐）

在仓库根目录（`matrix-intuition/`）装依赖：

```bash
pip install -r requirements.txt
```

这个文件里只有三样（你可以打开看一眼）：

| 包 | 干什么用 |
|---|---|
| `numpy` | 数表/数组运算，本课后段的主角 |
| `matplotlib` | 画图，配图就是它画的 |
| `pytest` | 跑测试，你的"考场" |

> ⚠️ **易踩坑：全局环境 vs 虚拟环境。**
>
> 如果你电脑上有很多 Python 项目，直接把包装进全局环境容易互相打架（不同项目要 numpy 不同版本）。建议先建一个干净的小房间（venv），把依赖关在里面：
>
> ```bash
> python3 -m venv .venv          # 建虚拟环境
> source .venv/bin/activate      # macOS/Linux 激活（Windows 用 .venv\Scripts\activate）
> pip install -r requirements.txt  # 在虚拟环境里装依赖
> ```
>
> 激活后命令行前面会多出 `(.venv)` 字样，表示你正在这个小房间里。以后跑测试、跑代码都要**先激活**它。嫌麻烦、且你机器干净，也可以直接用全局 Python——本课不强求。

## 3.3 两件工具，两个念头

### numpy：数表 = 数组

numpy 的核心叫 `ndarray`（n 维数组）。**你就把它想成"一张格子表"**：

- 一维数组 = 一行格子 `[3, 4]`（正好可以放一个向量！）；
- 二维数组 = 一张表格（行 $\times$ 列，正好可以放一个矩阵、放一张 embedding 表）。

它真正省事的地方是：**运算是对整张表一起做的**，不用你写循环。

```python
import numpy as np
a = np.array([3, 4])
b = np.array([1, 2])
print(a + b)     # → [4 6]，两个向量"整表相加"，一行搞定
```

本周你其实还**用不上** numpy（Day 1 用纯 Python 的 list 就够了，先建立"加/乘是怎么一步步来的"的直觉）；但从 Week 2 起，一切都会搬进 numpy。现在认识它，是为了让你心里有底："原来后面那些 `@` 矩阵乘，都是在给这张表做运算。"

### matplotlib：给我数据，我画图

matplotlib 只干一件事：**你告诉它"数据长什么样"，它给你画出来**。本课所有带精确坐标的配图，都是它的作品（`figures/` 里的生图脚本）。你不需要现在就会画图，但知道"配图不是我手残画的，是脚本对坐标精确算出来的"就够了——这正呼应第 1 章的告诫：**刻度要等距，图要对齐，所以交给脚本。**

> 📌 **划重点：** numpy = 数表（数组）的算盘，matplotlib = 数据的画笔。本周主角是"向量"这个念头，这两把工具是后面的得力助手，先打个照面。

## 3.4 先见证奇迹：跑参考答案（全绿）

现在做一件"反向"的事：你的代码还一行没写，先去把**参考答案的最终形态**跑一遍，看看 Day 1 结束后你会交出什么。

```bash
cd matrix-intuition        # 确保在仓库根目录
IMPL=reference pytest tests -k w1 -q
```

你会看到：

```text

```

`6 passed` 就是"本周 6 个测试，参考答案全过"。它验收的，正是你 Day 1 要亲手写的 7 个函数：造向量、加、减、数乘、取反、算长度、求位移。

> 💡 **你可能会问：为什么是 6 个测试，不是 7 个？函数不是 7 个吗？**
>
> 测试按"考点"打包，一个测试可能一次验收好几个函数（比如 `test_scale_and_neg` 同时考了数乘和取反）。7 个函数打包进 6 个测试，一起测完。等你写完代码，看到 `6 passed` 就说明 7 个函数全对了。

记住这一刻的感觉：**这是终点**。后面两天，你的任务就是让"战场"也跑到这个 `6 passed`。

## 3.6 IMPL 开关彻底讲清：同一份考卷，考两套代码

同一份测试，为什么能一会儿考 `reference/` 一会儿考 `matrixlab/`？靠的是环境变量 `IMPL`。它藏在 `tests/conftest.py` 里，规则一句话：

> `IMPL` 决定了测试去 `reference/` 还是 `matrixlab/` 里加载同名模块。**不写 `IMPL=xxx` 时默认就是 `matrixlab`（你的战场）。**

```bash
IMPL=matrixlab pytest tests -k w1   # 考你写的代码（等价于不写 IMPL）→ 现在全红
IMPL=reference pytest tests -k w1   # 考参考答案 → 全绿
```

这两个开关的用处：

- **`IMPL=reference`**：你想"偷看终点"时用。写完怀疑自己写得不对？先跑一下 reference 确认"题目本身是能过的"，排除"题出错了"的可能。
- **`IMPL=matrixlab`（默认）**：检验你自己的成果。这是你的主战场，每天写完就对着它看红变绿。

> ⚠️ **易踩坑：** `IMPL=reference` 是"看答案的效果"，**不是你通过考试**。别以为在终端里敲了 `IMPL=reference` 就等于自己实现了——它跑的是 `reference/` 里别人的代码。你要让**默认命令** `pytest tests -k w1`（不带 IMPL）变绿，才算数。

### 一个总括的三件套地图

```
matrix-intuition/
├── learning-guide/week1/   ← 读：本章正在看的教程
├── matrixlab/vec2d.py      ← 写：你的战场，7 个 TODO（唯一要动的地方）
├── reference/vec2d.py      ← 看：参考答案，卡住 20 分钟再看
└── tests/test_w1_vec2d.py  ← 考：6 个测试，已经写好、已经验证过
```

本周你**只动 `matrixlab/vec2d.py` 这一个文件**，其它一处都不改。

## 3.7 卡住怎么办（这条规则会救你很多时间）

整套教程只有一条求助规则：**卡住 20 分钟，就去看参考答案**。

1. 打开 `reference/` 里**同名文件**（你写 `vec2d.py` 卡住了，就看 `reference/vec2d.py`）；
2. 只看你卡住的那**一个函数**，别整篇读完——给后面的函数留点"自己想到"的机会；
3. 看懂后**合上它，凭理解自己重写一遍**，再跑测试验证；
4. 还卡？把报错、你的代码、对应测试名放在一起看——测试名和注释里往往藏着提示（比如 `test_length` 就明说"勾股定理"）。

参考答案是用来"点醒"你的，不是用来"誊写"的——抄一遍和写一遍，吸收效果差十倍。
