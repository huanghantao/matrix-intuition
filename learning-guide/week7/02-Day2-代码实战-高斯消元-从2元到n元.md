# Day 2：代码实战——高斯消元：从 2 元到 n 元

> 本章你将：
> - 把初中那套"加减消元"拆成两个机械步骤：**消元**（把某列下面全消成 0）和**回代**（从下往上解出每个未知数）；
> - 学会 **选主元**——当前要除的数恰好是 0 时，换一行绝对值更大的上来，避免除以 0；
> - 实现 `matrixlab/gauss.py` 里的 `solve_linear`，一个能解**任意 n 元**一次方程组的函数；
> - 亲手把一个 $3 \times 3$ 例子手算一遍（答案 $x = 2,\ y = 3,\ z = -1$），再跑 `pytest tests -k w7_gauss` 到绿。

---

## 2.1 昨天的题，今天要"机械化"

昨天我们解的是二元方程，两行纸就能搞定。但真实世界里，方程组可能有三元、十元、甚至一百元（一百个未知数、一百个方程）。n 一大，人脑手算直接崩——所以我们需要一套**不用动脑、只要照步骤走**的算法，让计算机去执行。

好消息是：**你初中学过的"加减消元法"，本身就是一套几乎可以机械化的步骤**。我们只差把它拆得足够细，细到每一小步都能写成 Python 的一行循环。

这就是**高斯消元（Gaussian elimination）**——名字唬人，骨子里就是"加减消元 + 回代"的流水线作业。

---

## 2.2 先热身：2 元，用人话走一遍

拿昨天的例子 $x + y = 3$、$x - y = 1$，把它俩的系数抽出来、和等号右边的数拼在一起，写成一个**增广矩阵（augmented matrix）**：

```
系数矩阵 A          右边 b       增广矩阵 [A | b]
┌        ┐    ┌   ┐      ┌          ┐
│ 1   1  │    │ 3 │      │ 1   1   3 │
│ 1  −1  │    │ 1 │      │ 1  −1   1 │
└        ┘    └   ┘      └          ┘
```

"增广"的意思就是：**把 b 那一列直接粘到 A 右边**，方便一起操作——反正消元时每一行等号两边做同样的运算，粘在一起同步做，最省心。

现在走两步：

**第 1 步——消元**：用第 1 行把第 2 行第 1 列（数字 1）消成 0。怎么消？第 2 行减去第 1 行：

```
第 2 行：  [ 1  −1   1 ]
减 第 1 行： [ 1   1   3 ]
──────────────
新第 2 行：  [ 0  −2  −2 ]
```

增广矩阵变成：

```
┌          ┐
│ 1   1   3 │
│ 0  −2  −2 │
└          ┘
```

现在第 2 行只剩下一个未知数了：$-2y = -2$，即 $y = 1$。

**第 2 步——回代**：从最后一行开始，一层层把解"代回去"：

- 最后一行：$-2y = -2$ → $y = 1$；
- 上一行：$x + y = 3$，把 $y = 1$ 代进去 → $x + 1 = 3$ → $x = 2$。

答案 $(2, 1)$。这两个步骤——**消元**（把下三角全变成 0）+ **回代**（从下往上解）——就是高斯消元的全部。n 元时，只是"消元"要多跑几轮、"回代"要从第 n 行往上爬。

> 💡 **你可能会问：为什么非要先消成 0，不能直接解吗？**
>
> 人脑能"看"出来，但计算机是瞎子，它只能执行固定的规则。"把下面一列全消成 0"就是一条固定规则：消完以后，最后一行**恰好只剩最后一个未知数**，可以直接读出；再往上每行都只有一个新未知数，代回去即可。**消元的目标，就是把方程组打扮成"倒三角形"**，让回代变得傻瓜化。

## 2.3 $3 \times 3$ 手算一遍（重要：明天测试就用它）

来真的了。这是 `test_solve_3x3` 里的那道题，请你跟着我，一步一步算：

$$
\begin{aligned}
2x + y - z &= 8 \\\\
-3x - y + 2z &= -11 \\\\
-2x + y + 2z &= -3
\end{aligned}
$$

写成增广矩阵：

```
┌              ┐
│  2   1  −1   8 │
│ −3  −1   2  −11 │
│ −2   1   2  −3 │
└              ┘
```

**第 1 轮消元（消掉第 1 列下面两个数）**：用第 1 行当"武器"，把第 2、3 行的第 1 列消灭。

- 第 2 行要消掉 $-3$，需要加"第 1 行的 $3/2$ 倍"（因为 $2 \times 3/2 = 3$，$-3 + 3 = 0$）：
  ```
  新第2行 = 第2行 + (3/2)·第1行
  (−3 + 3, −1 + 1.5, 2 − 1.5, −11 + 12) = (0, 0.5, 0.5, 1)
  ```
- 第 3 行要消掉 $-2$，需要加"第 1 行的 1 倍"（$2 \times 1 = 2$，$-2 + 2 = 0$）：
  ```
  新第3行 = 第3行 + 1·第1行
  (−2 + 2, 1 + 1, 2 − 1, −3 + 8) = (0, 2, 1, 5)
  ```

增广矩阵变成：

```
┌             ┐
│  2  1   −1   8 │
│  0  0.5  0.5  1 │
│  0  2    1    5 │
└             ┘
```

**第 2 轮消元（消掉第 2 列在第 3 行的 2）**：用第 2 行当武器，把第 3 行第 2 列消灭。

第 3 行要消掉 2，需要加"第 2 行的 $-4$ 倍"（$0.5 \times (-4) = -2$，$2 + (-2) = 0$）：

```
新第3行 = 第3行 − 4·第2行
(0, 2 − 2, 1 − 2, 5 − 4) = (0, 0, −1, 1)
```

增广矩阵变成"倒三角形"：

```
┌              ┐
│  2  1   −1   8 │
│  0  0.5  0.5  1 │
│  0  0   −1   1 │
└              ┘
```

消元完成！最后一行只剩一个未知数了。

**回代（从下往上）**：

- 第 3 行：$-z = 1$ → **z = -1**；
- 第 2 行：$0.5y + 0.5z = 1$，代 z = -1 → $0.5y - 0.5 = 1$ → $0.5y = 1.5$ → **y = 3**；
- 第 1 行：$2x + y - z = 8$，代 y = 3、z = -1 → $2x + 3 + 1 = 8$ → $2x = 4$ → **x = 2**。

答案 **x = (2, 3, -1)**。和测试 `test_solve_3x3` 断言的 `[2, 3, -1]` 完全一致。

> 📌 **划重点：高斯消元 = 两段循环。** 前半段"消元"，从第 0 列到第 $n-2$ 列，每一列都把它下面所有行消成 0；后半段"回代"，从第 $n-1$ 行往上，每行解出一个未知数。整件事没有任何一处需要"聪明"，全是照方抓药——所以才能交给计算机。

## 2.4 一个没人和你说过的坑：除零

上面每一步都在"用某行把下面的消掉"，具体实施时都要**除以当前行的主对角元（叫主元，pivot）**。比如第 2 轮，我们要除以第 2 行的第 2 列那个数 `0.5`。

但万一这个数是 **0** 呢？除 0 直接崩。看 `test_solve_needs_pivot` 这道题：

```
0x + y = 2      ← 第 1 个式子没有 x！
x + 0y = 3
```

增广矩阵：

```
┌          ┐
│ 0  1   2 │
│ 1  0   3 │
└          ┘
```

第 1 行的主元是 0，你根本没法拿它去消第 2 行的 x。怎么办？

答案是**换行（选主元）**：把第 1 行和第 2 行**对调**，让一个有值的行顶上来当主元：

```
┌          ┐
│ 1  0   3 │
│ 0  1   2 │
└          ┘
```

现在主元是 1，一切照常（这个例子消元都省了，直接回代：x = 3, y = 2）。

> 💡 **你可能会问：为什么"选主元"要挑**绝对值最大 **的那一行，而不是随便挑一个非 0 的？**
>
> 因为浮点数有精度。如果主元特别小（比如 0.0000001），你会拿一个巨大的倍数去消别的行，别的行里的数会被放大得离谱，精度哗哗掉，最后答案偏差很大。挑**本列绝对值最大**的那一行换上来，能让每一步的倍数都"温柔"一点，数值更稳。这就是"**部分主元选取（partial pivoting）**"。我们的实现里，正是用 `max(range(col, n), key=...)` 找出绝对值最大的行来交换。

> ⚠️ **易踩坑：换行了，右边那列（b）也一定跟着换。** 增广矩阵是 [A | b] 粘起来的整体，换行是"整行换"，b 那一列跟着走。别只换了 A 的一半把 b 落下了，答案会错得莫名其妙。

## 2.5 写代码：`solve_linear` 逐行讲解

现在打开 `matrixlab/gauss.py`，把 `solve_linear` 的 `raise NotImplementedError` 换成真实现。我们对着思路一步步写。

**第 0 步——造增广矩阵**：

```python
def solve_linear(A: list, b: list) -> list:
    n = len(A)
    # 增广矩阵：把 b 拼到 A 右边
    M = [row[:] + [b[i]] for i, row in enumerate(A)]
```

`row[:]` 是**复制**这一行（不碰原 A），再把 `b[i]` 追加到末尾。这样每行变成 `[a_i1, ..., a_in, b_i]`，长度 n+1。

**第 1 步——消元：外层循环每一列，内层把该列下面的行全消成 0**：

```python
    for col in range(n):
        # 选主元：在 col 列找绝对值最大的行，换到当前行来
        pivot = max(range(col, n), key=lambda r: abs(M[r][col]))
        if abs(M[pivot][col]) < 1e-12:
            raise ValueError("矩阵奇异：方程没有唯一解")
        M[col], M[pivot] = M[pivot], M[col]

        # 消元：把 pivot 行以下的每一行的 col 列消成 0
        for r in range(col + 1, n):
            factor = M[r][col] / M[col][col]
            for c in range(col, n + 1):
                M[r][c] -= factor * M[col][c]
```

逐句看：

- `pivot = max(range(col, n), key=lambda r: abs(M[r][col]))`：在 `col` 列、从 `col` 行往下找**绝对值最大**的那一行（`key` 是"这一行第 col 列的绝对值"）。这就是选主元。
- `if abs(M[pivot][col]) < 1e-12: raise ValueError(...)`：如果找到的最大主元都接近 0，说明这一列整列都是 0，方程没有唯一解（对应昨天说的"直线平行/重合"），抛异常。
- `M[col], M[pivot] = M[pivot], M[col]`：把选中的主元行换到当前位置（Python 就一行交换两个列表）。
- 内层 `for r`：对主元行**下面**的每一行 `r`，算一个 `factor = M[r][col] / M[col][col]`（要消掉的数 ÷ 主元），然后让第 r 行减 `factor` $\times$ 主元行，把它的 `col` 列消成 0。注意 `c` 从 `col` 走到 `n`（含 b 那列），因为主元行 `col` 之前的数本来就是 0，不用动。

**第 2 步——回代：从最后一行往上解**：

```python
    x = [0.0] * n
    for i in range(n - 1, -1, -1):
        s = M[i][n]                       # 等式右边
        for j in range(i + 1, n):
            s -= M[i][j] * x[j]           # 把已经解出的分量搬过去
        x[i] = s / M[i][i]                # 求出第 i 个分量
    return x
```

逐句看：

- `for i in range(n - 1, -1, -1)`：从最后一行（$n-1$）往上爬到第 0 行。
- 解第 i 行的方程是 $M[i][i]\cdot x_i + \sum_{j>i} M[i][j]\cdot x_j = M[i][n]$。因为消元完了，第 i 行里 `j < i` 的系数全已经是 0，只剩 `x_i` 和它右边（已经解出来的）那些分量。
- `s = M[i][n]`，然后逐个减去 `M[i][j] * x[j]`（这些 `x[j]` 之前已经解出来了），剩下的就是 $M[i][i]\cdot x_i$，除以 `M[i][i]` 得到 `x_i`。

对比第 2.3 节的手算：当 `i = 2`（最后一行），内层 `j` 从 3 到 2 是空循环，`s = M[2][3] = 1`，`x[2] = 1 / (-1) = -1`，正是 $z = -1$。当 `i = 1`，先减 `M[1][2]*x[2]`，再算 y。和手算一模一样。

| 测试 | 它在考你什么 |

| `test_solve_identity` | 单位矩阵直接解出 b 本身 |

如果还红，按顺序排查：

1. **换行换干净了吗**——是不是只换了 A 忘了 b（其实你先拼增广矩阵，换 `M` 整行就不会有这个坑）；
2. **内层 `c` 的范围**——消元时 `c` 要从 `col` 走到 `n`（含最后 b 那列），漏掉 b 列，右边就不同步了；
3. **回代的循环方向**——`range(n-1, -1, -1)` 是从下往上，写顺了会乱；
4. 卡 20 分钟，看 `reference/gauss.py`（只看卡住的那一段），合上重写。

>
> 前者告诉 pytest "用 `reference/` 里的参考答案当被测对象"，所以**什么都不用写也全绿**——那是"终点"；你真正写的是 `matrixlab/` 里的战场版，所以**不带 `IMPL`** 直接 `pytest tests -k w7_gauss` 测的才是你的代码。这个机制 Week 1 第 3 章讲过，本周天天用。

## 2.7 小结

- ✅ 高斯消元 = **消元**（把每列下方消成 0，做成倒三角）+ **回代**（从下往上解出每个未知数）。
- ✅ 增广矩阵 = 把 b 粘到 A 右边，方便整行一起操作。
- ✅ 选主元：主元为 0 时换**绝对值最大**的行上来，既防除零、又保精度。
- ✅ `solve_linear`：外层循环选主元 + 消元，内层回代，任意 n 元通用。
- ✅ `pytest tests -k w7_gauss` → 6 passed，$3\times 3$ 手算答案 (2, 3, -1) 与测试一致。

你手里现在多了一台"万能解方程机器"。明天的题会用它——但明天的方程**根本没有精确解**，这才是真正的风浪。
